Where AI Systems Actually Break

In brief: As companies wire AI into operations, failures move from the clever parts to the shared ones: a single data source, a single queue, a single login. Leaders should map what everything waits on before they add another agent.

On a Friday evening, a branch manager called to say the system was slow. Orders were taking more than a minute to reach the kitchen. The staff blamed the internet, then the tablets, then the software.

It was one printer. Every ticket in that branch passed through a single queue, and the queue waited politely for a dead machine to reply before moving on. One quiet failure at one station set the pace for the whole restaurant. Removing it from the configuration took seconds. Finding it took most of the evening.

I have thought about that printer more than any model release this year, because it is exactly how AI systems fail in practice.

Failure has moved

The public conversation about AI risk is about the model: hallucination, bias, the wrong answer delivered with confidence. Those risks are real. In our companies, though, they are rarely what breaks things.

What breaks things are the shared dependencies that AI quietly multiplies. When one agent reads the ERP, a unit-of-measure error in the ERP is a nuisance. When six agents read it, for costing, purchasing, reporting and stock alerts, the same error becomes six confident and consistent wrong answers. The model did its job perfectly. The ground it stood on was soft.

AI does not create new single points of failure. It finds the ones you already had and puts weight on them.

A dependency audit in three questions

Before we add an agent now, we ask three questions. They take an afternoon and have saved us weeks.

  1. What does it read? Name the exact source of truth. If the answer is a spreadsheet someone updates, the agent inherits that person’s holidays.
  2. What else reads the same thing? Count the consumers. Every additional agent on the same source raises the cost of that source being wrong.
  3. What is the one move that takes it out of the path? For the printer, it was removing it from the configuration. For an agent, it is a kill switch someone non-technical can use at nine on a Friday night.

Fix the ground, not the output

The tempting response to a wrong AI answer is to patch the answer: a filter here, an exception there, a dashboard rule that hides the strange number. We did that early on. It made each report look right and the system as a whole less true.

The better discipline is to treat every wrong answer as a pointer to the source. When an agent recommended buying far more of an ingredient than any kitchen could use, the cause was not the agent. Stock had been consumed in production without the receipt ever being recorded, so the system believed we were deep in deficit. We fixed the recording, not the recommendation.

What leaders should do

  • Ask for a one-page map of what your AI systems read, and circle anything more than two of them share.
  • Give every automated process an off switch and a named person allowed to use it.
  • When an AI answer is wrong, fund the fix at the source, even when patching the output is faster.

Resilience is not a system where nothing breaks. It is one where the broken part can be lifted out of the line before the next table orders.
